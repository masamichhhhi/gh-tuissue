# Implementation Plan

- [x] 1. プロジェクト初期化とGitHub CLI拡張機能セットアップ
- [x] 1.1 Goモジュールの初期化と依存パッケージのセットアップ
  - Goモジュールを初期化し、Bubble Tea v2、Lip Gloss、Bubbles、go-gh v2、glamourの依存を追加する
  - gh extensionとしてのエントリポイント（mainパッケージ）を作成し、`--repo`フラグ、`--project`フラグ（Project番号指定）、`--version`フラグを処理する
  - カレントディレクトリのGitリモートURLからリポジトリのowner/nameを自動検出する機能を実装する
  - `--repo owner/name`フラグが指定された場合はそちらを優先する
  - Bubble Teaプログラムを`tea.WithAltScreen()`オプション付きで起動し、終了時にターミナル画面をクリアする
  - _Requirements: 1.1, 1.2, 1.5, 1.6, 8.4_

- [x] 2. GitHub APIクライアントとドメインモデル
- [x] 2.1 ドメインモデルの定義
  - Issue、Label、User、Milestone、Comment、PageInfoなどのドメイン型を定義する
  - IssueにNodeIDフィールド（GraphQLグローバルノードID）を追加する
  - ProjectV2関連のドメイン型（ProjectSummary、ProjectInfo、StatusField、StatusOption、ProjectItem）を定義する
  - エラー型（AppError、ErrorCode）を定義し、認証エラー・ネットワークエラー・権限エラー・ProjectNotFound・StatusFieldMissing等を分類する
  - _Requirements: 5.7_

- [x] 2.2 (P) GitHub APIクライアントの実装
  - go-gh v2のDefaultGraphQLClient/DefaultRESTClientを利用して認証済みAPIクライアントを構築する
  - GraphQLクエリの実行メソッドとREST（GET/POST/PATCH）メソッドを実装する
  - gh CLIが未インストールまたは未認証の場合、`gh auth login`の実行を促すエラーメッセージを返す
  - _Requirements: 1.3, 1.4_

- [x] 2.3 IssueServiceの実装
  - GraphQLクエリでIssue一覧を取得する機能を実装する（ラベル・アサイニー・マイルストーン・NodeIDを含む）
  - カーソルベースのペジネーションに対応する
  - Issue作成（タイトル・本文・ラベル・アサイニー・マイルストーン指定）を実装する
  - Issue更新（タイトル・本文・ラベル・アサイニー・マイルストーン変更）を実装する
  - コメント一覧取得とコメント追加を実装する
  - APIエラー時はドメインエラー型でラップして返す
  - _Requirements: 5.2, 5.3, 5.4, 5.5, 5.6, 5.7, 6.3, 7.2, 9.1, 9.3_

- [x] 2.4 (P) ProjectServiceの実装
  - リポジトリに紐づくProjectV2の一覧を取得する機能を実装する
  - 指定されたProjectのフィールド情報を取得し、「Status」名のSingleSelectFieldとそのoptionsを抽出する
  - ProjectV2Itemの一覧をペジネーション付きで取得し、各Itemのステータス値とIssue情報を返す
  - IssueのステータスをGraphQLミューテーション（updateProjectV2ItemFieldValue）で変更する機能を実装する
  - IssueをProjectに追加する機能（addProjectV2ItemById）を実装する
  - Projectが存在しない場合やStatusフィールドが見つからない場合はProjectNotFound/StatusFieldMissingエラーを返す
  - _Requirements: 2.2, 5.1_

- [x] 2.5 (P) RepoServiceの実装
  - リポジトリのラベル一覧を取得する機能を実装する
  - リポジトリのコラボレーター一覧を取得する機能を実装する
  - リポジトリのマイルストーン一覧を取得する機能を実装する
  - _Requirements: 1.5, 3.1_

- [x] 3. Appシェルとキーボードナビゲーション基盤
- [x] 3.1 Appモデルの実装
  - Bubble Tea v2のtea.Modelインターフェースを実装するAppモデルを構築する
  - 画面状態（Board/Detail/Editor/Filter/Help）の遷移管理を実装する
  - ターミナルのウィンドウサイズ変更イベントを処理し、各画面に伝播する
  - グローバルキーバインド（q終了、?ヘルプ、Escで前の画面に戻る）を処理する
  - Vimキーバインド（h/j/k/l）と矢印キー（←/↓/↑/→）の両方でナビゲーション操作をサポートする
  - 画面下部にコンテキストに応じたキーバインドヒントを表示するステータスバーを実装する
  - 編集操作（タイトル編集・本文編集・プロパティ変更）完了後に正しくカンバンボード画面へ復帰する遷移ロジックを実装する
  - _Requirements: 5.8, 8.1, 8.2, 8.3, 8.4, 8.5_

- [x] 4. カンバンボード表示
- [x] 4.1 ボードモデルの実装
  - ProjectServiceから取得したステータスoptionsに基づき、動的なN個のカラムを構成してカンバンボードを描画する
  - 各Issueカードをステータスに応じたカラムに配置し、Issue番号、タイトル、ラベル（色付き）、アサイニーを表示する
  - Lip Glossでカード・カラムのスタイリング（ボーダー、パディング、カラー）を適用する
  - ターミナルサイズとカラム数に応じてカラム幅を動的に分配し、レイアウトを調整する
  - _Requirements: 2.1, 2.2, 2.3, 2.5_

- [x] 4.2 ボードナビゲーションとスクロール
  - h/lキーおよび←/→矢印キーでカラム間の移動を実装する
  - j/kキーおよび↓/↑矢印キーでカラム内のIssueカード間の移動を実装する
  - Issueの数がカラムの表示領域を超えた場合のスクロール処理を実装する
  - EnterキーでフォーカスされたIssueの詳細画面への遷移を実装する
  - フィルタ結果が0件の場合に空状態メッセージを表示する
  - _Requirements: 2.4, 3.4, 8.1, 8.2_

- [x] 4.3 ステータス移動コマンドの実装
  - カンバンボード上で選択中のIssueを隣接するステータス（カラム）に移動するコマンドを実装する
  - 左移動コマンド（1つ前のステータスへ）と右移動コマンド（1つ後のステータスへ）を提供する
  - ProjectServiceのMoveItemStatusを呼び出し、GitHub Projects V2のステータスを更新する
  - 移動成功時はIssueを移動先カラムに再配置して表示を更新する
  - 移動失敗時はエラーメッセージを表示し、元のカラムに維持する
  - 最左カラムで左移動、最右カラムで右移動した場合は何もしない
  - _Requirements: 5.1, 5.7_

- [x] 4.4 データ取得とローディング表示
  - 起動時にProjectServiceを通じてProject情報とProjectItemsを非同期で取得しカンバンに表示する
  - Projectが指定されていない場合はリポジトリのProject一覧から選択させるか、フォールバックとしてOpen/Closedの2カラムで表示する
  - データ取得中はローディングインジケータ（スピナー）を表示する
  - リフレッシュ操作（Rキー等）で最新データを再取得して表示を更新する
  - APIタイムアウト時はエラーメッセージを表示し、直前のデータでの表示を維持する
  - _Requirements: 2.1, 2.2, 9.1, 9.2, 9.3_

- [x] 5. Issue詳細ビュー
- [x] 5.1 詳細表示の実装
  - Issue詳細画面にタイトル、ステータス、ラベル、アサイニー、マイルストーン、作成日、更新日を表示する
  - Issue本文をglamourでMarkdownレンダリングして表示する
  - コメント一覧を表示し、各コメントに著者と作成日を付与する
  - viewportコンポーネントを使用して長い内容のスクロールを実装する
  - _Requirements: 4.1, 4.2, 4.3, 4.4_

- [x] 5.2 プロパティ編集操作
  - ラベルの追加・削除をリポジトリのラベル一覧からのマルチセレクトUIで実装する
  - アサイニーの変更をコラボレーター一覧からの選択UIで実装する
  - マイルストーンの変更をマイルストーン一覧からの選択UIで実装する
  - API更新失敗時はエラーメッセージを表示し、変更前の状態にUIを復帰する
  - 編集完了後にカンバンボード画面に正しく遷移する
  - _Requirements: 5.4, 5.5, 5.6, 5.7, 5.8_

- [x] 6. エディタ機能（インライン・外部エディタ）
- [x] 6.1 インラインテキスト編集
  - Issueタイトルのインライン編集機能を実装する（textinputコンポーネント使用）
  - 編集確定時にAPIへ変更を反映する
  - 編集完了後にカンバンボード画面へ復帰する
  - _Requirements: 5.2, 5.8_

- [x] 6.2 外部エディタ連携
  - $EDITOR環境変数で指定されたエディタを起動してIssue本文を編集する機能を実装する（tea.ExecCmd使用）
  - エディタで編集された内容をAPI経由でGitHubに反映する
  - コメント追加時にも外部エディタを起動する
  - エディタ終了後にエラーが発生した場合、入力内容を保持して再試行可能にする
  - 外部エディタ終了後にカンバンボード画面（またはIssue詳細画面）へ正しく復帰する
  - _Requirements: 5.3, 5.8, 7.1, 7.3_

- [x] 6.3 Issue新規作成フロー
  - 新規Issue作成のトリガー操作（キーバインド）を実装する
  - タイトル入力フォームを表示し、本文は外部エディタで入力する
  - 作成時にラベル・アサイニー・マイルストーンを任意で設定できるUIを実装する
  - 作成成功後にカンバンボードを更新して新しいIssueを表示する
  - _Requirements: 6.1, 6.2, 6.3, 6.4_

- [x] 7. フィルタリング・ソート機能
- [x] 7.1 (P) フィルタパネルの実装
  - ラベル、アサイニー、マイルストーンによるフィルタリング選択UIを実装する
  - ソート条件（作成日/更新日/コメント数）と並び順（昇順/降順）の選択UIを実装する
  - リポジトリのメタデータ（ラベル一覧、コラボレーター一覧、マイルストーン一覧）をRepoServiceから取得して選択肢を表示する
  - _Requirements: 3.1, 3.2_

- [x] 7.2 フィルタの適用と表示
  - フィルタ条件をカンバンボードのIssue一覧に適用し、該当するIssueのみ表示する
  - 適用中のフィルタ条件をボード上部のバーに表示する
  - フィルタ結果が0件の場合に該当Issueなしのメッセージを表示する
  - _Requirements: 3.1, 3.2, 3.3, 3.4_

- [x] 8. ヘルプ画面
- [x] 8.1 キーバインドヘルプの実装
  - `?`キーで表示するキーバインドヘルプ画面を実装する
  - 画面ごとに利用可能なキーバインドの一覧を表形式で表示する（Vim/矢印キー両方、ステータス移動コマンドを含む）
  - Esc/qキーでヘルプ画面を閉じて前の画面に戻る
  - _Requirements: 8.3_

- [x] 9. 設定ファイルによるProject紐付け永続化
- [x] 9.1 ConfigServiceの実装
  - リポジトリルートの`.gh-tuissue.json`を読み込み、Project番号を取得する機能を実装する
  - 設定ファイルが存在しない場合はnilを返し、初回起動であることを示す
  - Project番号を含む設定をJSON形式で`.gh-tuissue.json`に書き込む機能を実装する
  - JSONパースエラー時はデフォルト値にフォールバックし、警告を返す
  - エラー型にConfigLoad/ConfigSaveエラーコードを追加する
  - _Requirements: 10.4, 10.5_
  - _Contracts: ConfigService API_

- [x] 9.2 起動フローへの設定ファイル統合
  - エントリポイントに設定ファイル読み込みロジックを組み込み、保存済みProject番号を自動的に使用する
  - `--project`フラグが指定された場合は設定ファイルの値より優先する（設定ファイルは上書きしない）
  - `--config`フラグを追加し、指定時はProject選択フローを強制的に再表示する
  - 設定ファイルのProject番号が無効（Projectが削除済み等）の場合、エラーメッセージを表示してProject選択UIにフォールバックする
  - _Requirements: 10.5, 10.6, 10.7, 10.8_

- [x] 9.3 Project選択UIの実装
  - 初回起動時に「Projectを紐付けますか？」のYes/No確認画面を表示する
  - Yes選択時にProjectServiceからリポジトリのProject一覧を取得し、カーソル移動式の選択UIを表示する
  - No選択時はProject紐付けなしの状態でOpen/Closedの2カラムカンバンに遷移する
  - Project選択確定時にConfigServiceで設定ファイルに保存し、選択されたProjectのカンバンボード表示に遷移する
  - `--config`フラグ時およびProject無効時にも同じ選択フローを再利用する
  - Appモデルの画面状態にProjectSelect画面を追加し、遷移を管理する
  - _Requirements: 10.1, 10.2, 10.3, 10.4, 10.7, 10.8_
  - _Contracts: ProjectSelectModel State, ProjectService API, ConfigService API_

- [x] 10. カラム表示・非表示の切り替え
- [x] 10.1 (P) カラム非表示・復元ロジックの実装
  - ボードモデルにカラムごとの表示・非表示状態を管理する仕組みを追加する
  - カラム非表示キー（`d`キー）でフォーカス中のカラムを非表示にし、残りのカラムで表示幅を再分配する
  - カラム全復元キー（`D`キー）で非表示にした全カラムを元の位置に復元する
  - 非表示時にカーソルが非表示カラム上にある場合、隣接する表示カラムにカーソルを移動する
  - 最低1つのカラムが常に表示された状態を維持し、全カラム非表示の操作を拒否してステータスメッセージで通知する
  - ステータスバーに非表示カラム数を表示する（例: "2 columns hidden"）
  - _Requirements: 11.1, 11.2, 11.3, 11.4_
  - _Contracts: BoardModel State_

- [x] 10.2 ヘルプ画面へのカラム操作キーバインド追加
  - ヘルプ画面のキーバインド一覧にカラム非表示（`d`）と全復元（`D`）を追加する
  - カンバンボード画面のキーバインドヒントにカラム操作のヒントを追加する
  - _Requirements: 11.1, 11.2, 8.3, 8.5_

- [x] 11. Issue詳細画面からのプロパティインライン編集
- [x] 11.1 汎用選択UIコンポーネントの実装
  - マルチセレクト（ラベル・アサイニー）とシングルセレクト（マイルストーン）の両方に対応する選択UIを実装する
  - j/kキーまたは↓/↑矢印キーで項目間を移動し、Spaceキーで選択・解除（マルチセレクト）を行う
  - 現在のIssueに設定済みの値をプリセレクト状態で表示する
  - Enterキーで選択確定、Escキーでキャンセルして選択UIを閉じる
  - _Requirements: 12.1, 12.2, 12.3, 12.4_

- [x] 11.2 Issue詳細画面へのインライン編集統合
  - Issue詳細画面で`l`キー押下時にラベル選択UIを直接表示する（RepoServiceからラベル一覧を取得）
  - Issue詳細画面で`a`キー押下時にアサイニー選択UIを直接表示する（RepoServiceからコラボレーター一覧を取得）
  - Issue詳細画面で`m`キー押下時にマイルストーン選択UIを直接表示する（RepoServiceからマイルストーン一覧を取得）
  - 既存のプレースホルダメッセージ（"use filter panel (not yet inline)"）を実際の選択UIに置き換える
  - 選択確定時にIssueServiceを通じてGitHub APIに変更を反映する
  - API更新成功時はIssue詳細画面のプロパティ表示を更新する
  - API更新失敗時はエラーメッセージを表示し、変更前の状態を維持する
  - メタデータ（ラベル・コラボレーター・マイルストーン一覧）をセッション内でキャッシュし、同一セッションの再取得を回避する
  - ヘルプ画面にIssue詳細画面のインライン編集キー（`l`/`a`/`m`）を追加する
  - _Requirements: 12.1, 12.2, 12.3, 12.4, 5.7_
  - _Contracts: DetailModel State, SelectModel State, IssueService API, RepoService API_

- [x] 12. 統合テストとビルド設定

  - GitHub Actionsのワークフローにgh-extension-precompileを設定し、タグプッシュ時のマルチプラットフォームビルドを構成する
  - リポジトリに`gh-extension`トピックタグを設定する
  - _Requirements: 1.1_

- [x] 12.2 全体統合の確認
  - 起動→設定ファイル読み込み→Project情報取得→カスタムステータスカラムのカンバン表示の一連のフローが正しく動作することを確認する
  - 初回起動→Project紐付け確認UI→Project選択→設定ファイル保存→次回起動での自動読み込みフローを確認する
  - `--project`フラグ指定時に設定ファイルより優先されること、`--config`フラグでProject再選択が可能なことを確認する
  - 設定ファイルのProject番号が無効な場合にProject選択UIが再表示されることを確認する
  - ステータス移動（左右コマンド）によるIssueのカラム間移動と表示更新を確認する
  - カラム非表示→レイアウト再調整→全復元が正しく動作し、最低1カラムの表示が維持されることを確認する
  - Issue詳細画面からl/a/mキーでインライン編集→選択→API反映→画面更新が正しく動作することを確認する
  - 各編集操作（タイトル・本文・ラベル・アサイニー・マイルストーン）後にカンバンボード画面またはIssue詳細画面へ正しく復帰することを確認する
  - Vim/矢印キーの両方でナビゲーションが正しく動作することを確認する
  - TUI終了時にターミナル画面がクリアされ、残像が残らないことを確認する
  - フィルタ適用→解除、Issue新規作成→表示更新のフローを確認する
  - エラーケース（未認証、ネットワーク障害、API失敗、Project未存在、Statusフィールド未設定、設定ファイル破損、インライン編集失敗）の挙動を確認する
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2, 5.1, 5.7, 5.8, 8.1, 8.4, 9.1, 10.1, 10.2, 10.3, 10.4, 10.5, 10.6, 10.7, 10.8, 11.1, 11.2, 11.3, 11.4, 12.1, 12.2, 12.3, 12.4_
